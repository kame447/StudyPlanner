## Scope and ownership

Prevent the ordinary browser canvas from appearing white/light before React
mounts the existing dark startup video. Repository main, open PRs, startup
branches, and #483/#542 checkpoints were checked before implementation. No
existing white-flash fix was found. Diagnostics, inquiry navigation #621,
Home add motion, auth/readiness gates, video assets and playback stay separate.
No Issue, PR, remote branch, main update or deployment is authorized here.

## Implementation decision

The actual HTML has an empty root and no initial background. The full stylesheet
sets a light default before React mounts the dark splash. A permanent dark base
would interfere with normal themes; a route-aware script/marker would introduce
another lifecycle and duplicate route/theme policy. Use a head-inline CSS guard
that paints only while root content is absent. It covers both delayed CSS and
CSS-loaded/script-delayed startup without a timer, storage read or JS dependency.

The guard uses the same `:has()` browser capability already used by startup,
modal and theme styles. Native Chromium/Firefox/WebKit coverage is required;
source/unit checks alone do not prove painting or supported-device behavior.
Direct public/admin entry also gets a short dark empty canvas, then its ordinary
surface as soon as React commits. No video or additional wait is added there.
That intentional tradeoff avoids a second routing/theme implementation.

This removes a source-backed flash candidate, not a proven diagnosis of the
user's installed-PWA behavior. Browser/OS-owned launch screens before HTML is
received are outside this document's styling scope.
