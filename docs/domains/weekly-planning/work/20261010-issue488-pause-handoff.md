## 改善の目的と合意済みの設計

元の Stable V5 は、構造化できなかった発言を会話失敗として終えたり、質問の目的とユーザーの回答を違う意味へ結び付けたりした。実画面では、一度伝えたことの再質問、進捗を尋ねた回答から未来の予定量を勝手に確定すること、指定時刻や訂正が実プレビューへ反映されないこと、保存していない内容を「反映した」と説明すること、説明要求へ答えず同じ質問を繰り返すことが確認された。単に定型文を足して対症療法とするのではなく、会話が自然に続く一方で、Fact Graph と保存を厳格に守る境界に設計し直す。

合意した責務は、会話・意味解釈が自然言語と会話履歴から「発話の働き」と意味候補を取り出し、Interaction/Application が型付けされた候補と機械状態から apply / clarify / explain / aside / resume / recover などの扱いを選び、最後に決定論的な処理が schema、provenance、identity、revision、スケジューリング、プレビュー、明示承認、冪等保存を保証する3層である。中間層がユーザーの生の日本語を再解釈する「第二の意味解釈者」になってはならず、曖昧な理解を正式な Fact として無理に保存してはならない。構造化の失敗は会話を打ち切る理由ではなく、正式な状態変更ができなかったという事実として、次ターンに必要な確認を引き継ぐ。既存 Stable V5 の比較モードは検証用に維持し、機械的な保存権限や安全境界は弱めない。

2026年10月9日のユーザーの追加方針が優先する。通常の会話の質問文、質問順、確認文、終了文は一切定型テンプレートとしてハードコードしない。「どんな予定がありますか？」等も文面固定を指示したものではなく、会話場面の例示にすぎない。ユーザーは最初から作業量・週の総時間・日数・優先度を把握していない前提でよい。「来週は卒研を進めたい。できれば夜」のような漠然とした希望から、実際のカレンダーを利用し、少ない質問、選択肢、具体的な暫定候補、途中変更を使って共同で具体化する。最初から「合計何時間？」と聞く定型フローは採らない。見えている質問が過去の進捗を尋ねたなら、次の「合計2時間くらい」を未来の予定として黙って確定しない。質問目的の安全性は型付きの意味と検証で守るが、表現そのものは会話文脈を踏まえた AI に生成させる。AI が生成できない技術的エラーの最小限の文面だけを例外とし、保存・配置の真偽を捏造させない。

予定の対象も学習タスクだけとは限らない。固定予定だけを登録したい利用者に勉強の「作業」を無理に要求しない。現仕様で直接登録できなければ登録 UI を案内し、追加したかのような返答をしない。会話の状態遷移と、実プレビューの候補・未配置・訂正・承認状態・保存結果が一致することが製品上の成功基準である。

## 再開するときの順序と完成条件

まずユーザーが再開を明示し、Claude／Codex の残量と権限を確認する。使用枠の更新時刻になってもエージェントを自動起動しない。新オーケストレーターは最初に `AGENTS.md` と週間計画の `AGENTS.md`、#488 の Issue 本文・最新コメント、この文書、従来の work checkpoint、Orrery の個別レポートを読む。作業ツリーの `git status`、コミット SHA、取得済み最新 main、まだ存在する untracked、実行中のプロセスとコード所有者を確認する。すでに動いていたエージェントがいない前提でなく、起動前に再取得する。

次に未統合の S3a v3（スコープ分類→受理ルール）、S3b（自然な空き時間候補の提案・承諾・失効）、P2（速度に関する説明の自然化）、および残る検証器誤判定を、相互依存を踏まえた小さな統合単位として優先順にレビューする。既存の gate の held-out を新たな訓練例に転用して過適合させない。各変更は通った検証の正確な SHA とモデル経路を記録し、単体検査だけで受入完了にしない。実プレビューの日時・制約・数量、質問と回答の意味、修正した候補の取り消し、固定予定のみ、複合予定、翌日／当日の訂正、曖昧な相談、保存失敗時の復旧などをモデル変動を含め再 E2E する。

最終的な E2E の要求は、自然文入力から適切な確認または具体案、自由な訂正・相談、実プレビュー、明示承認、正しい永続保存、週・日・月の表示、再読込後の同一予定、再送／二重承認で重複なしまで成立することである。実際のモデル・画面・Worker／Firestore 境界と、scripted model／mock repository の成功を区別する。実保存はクリーンアップを証明できる専用アカウントか隔離環境に限り、本人の実データを破壊しない。安全に試せない範囲は未検証と明記する。通常文の定型文撲滅、安全な状態変更の境界、旧モードの差分なし、trace 永続化、フル `verify`、適用可能な CI／Browser、予算上限、セキュリティ、独立レビューを満たして初めて「実装完成」とする。
