# Learning Report Requirements

Status: canonical product specification

## 1. Purpose

ホーム画面の「今週の進捗 > 詳細を見る」から開く既存 `ReportView` を、現行のStudyPlanner主要UIと整合した学習レポート画面へ刷新する。

本画面は「分析専用の複雑なダッシュボード」ではなく、学習者が自分の学習量を短時間で確認し、必要なときだけ期間・教材単位へ掘り下げる二次画面として扱う。

画面を開いた直後に、少なくとも以下を把握できることを最優先とする。

- 今日の学習時間
- 今週の学習時間
- 今月の学習時間
- 累計学習時間

その下で、選択期間の推移と教材・科目別の内訳を確認できること。

## 2. Product position

レポートは主要タブではない。

主要ナビゲーションは現行どおり以下の5項目を維持する。

- AI計画
- 予定
- ホーム
- 教材
- 時間割

レポートはホームの週間進捗から開く二次導線とする。

旧 `AppViewSwitcher` はレポート画面でユーザーへ表示しない。

## 3. Reference boundary

他サービスに存在する「今日・今週・今月・累計の学習時間」「期間切替」「学習ログの集計」といった一般的な機能概念は参考にしてよい。

ただし、他サービス固有の画面構成、アイコン配置、文言、色、余白、画像、ブランド要素、SNSタイムライン等をそのまま複製しない。StudyPlannerの既存ナビゲーション、デザイントークン、データモデルへ合わせて再設計する。

今回、コメント、いいね、公開プロフィール、他ユーザーのタイムライン、ランキング等は実装しない。

## 4. Information hierarchy

画面は上から次の順序で構成する。

1. 学習レポートのタイトル/戻る導線
2. 今日・今週・今月・累計のサマリー
3. 日・週・月の期間粒度切替
4. 表示期間の前後移動
5. 教材フィルタ
6. 学習時間の推移
7. 教材・科目別の学習時間内訳
8. 決定論的に算出できる場合のみ短いインサイト
9. 現行PrimaryBottomNav

## 5. Summary cards

画面上部に以下4指標を常時表示する。

### Today

当日のActualから算出した学習時間。

同日の予定学習時間を安全に算出できる場合は補助情報として予定時間を表示してよい。

### This week

ユーザーの週開始曜日設定に整合した現在週のActual合計。

同期間のPlan合計を補助情報として表示してよい。

### This month

現在月のActual合計。

同期間のPlan合計を補助情報として表示してよい。

### Lifetime

当該ユーザーについて現在ロード済み/永続化済みの全Actualを対象とした累計学習時間。

累計は選択中の表示期間や教材フィルタでは変化しない。

### Layout

スマートフォンでは2列×2行を基本とする。

十分な横幅がある場合は4列表示を許容する。

各カードは数値を主役とし、補助情報のために高さを過度に増やさない。

## 6. Period granularity

`日 / 週 / 月` の3種類を提供する。

初期状態は `週` とする。

選択状態は色だけでなく背景・文字・`aria-pressed`等でも識別可能にする。

粒度切替時に更新する対象は以下。

- 表示期間
- 学習時間推移
- 教材・科目別内訳
- 対象期間合計
- インサイト

上部4サマリーは現在時点の固定サマリーとして扱い、日/週/月切替では変えない。

## 7. Period navigation

表示中の期間を中央に表示し、前後の矢印で期間を移動できる。

週表示の例:

`2026年08月20日〜2026年08月26日`

日表示では1日、月表示では年月を表示する。

矢印はアイコンのみでもよいが、必ずアクセシブルなラベルを持つ。

## 8. Material filter

初期値は `すべての教材` とする。

教材を選択した場合、選択期間内のActualのうち、その教材へ紐づく実績のみを推移・内訳・期間合計の対象とする。

教材との直接対応がないActualについては、既存データモデルのsubject情報を失わない。

教材名が長い場合でも横方向にはみ出さない。

## 9. Study-time trend

対象期間のActual学習時間を棒グラフとして表示する。

### Week

7日分を1日1本で表示する。

### Day

既存Actualが開始・終了時刻を持つ場合は時間帯別集計を許容する。ただしMVPでは、過度な集約ロジックを追加せず、期間内ログ一覧または妥当な時間帯集計へ縮退してよい。

### Month

日単位を基本とする。狭い画面で31ラベルを常時表示して可読性を壊さないよう、ラベル密度を制御する。

### General

グラフ見出し付近に対象期間の合計学習時間を表示する。

0分の日も期間構造として保持する。

グラフは視覚だけに依存せず、スクリーンリーダー向けに期間合計と各bucketの値へ到達できるラベルを持つ。

## 10. Plan comparison

既存Planデータから同期間の予定学習時間を安全に算出できる場合、実績と予定を比較可能にしてよい。

ただし今回の最低要件はActualの推移であり、予定比較のためにReportViewの実装を不必要に複雑化しない。

予定と実績を同時表示する場合、色だけで識別させない。

## 11. Material/subject breakdown

対象期間のActualを教材または科目単位に集約する。

各項目には以下を表示する。

- 教材名、または教材に紐づかない場合は科目名
- 学習時間
- 対象期間合計に占める割合
- 割合を示すプログレスバー

0分の項目は原則表示しない。

項目の合計学習時間は、フィルタ適用後の対象期間合計と一致しなければならない。

## 12. Insight

既存データから決定論的に算出できる場合のみ、短いインサイトを最大1件表示してよい。

許容例:

- 前の同粒度期間より学習時間が増えた/減った
- 予定時間を上回った日がある
- 1教材が期間学習時間の過半を占めている

禁止:

- LLMによる根拠のない学習評価
- 実績データに存在しない原因推定
- 必要以上の励まし文や説教的な文言

安全に生成できない場合はインサイト領域自体を表示しない。

## 13. Empty state

対象期間にActualがない場合でも、以下は維持する。

- 上部4サマリー
- 日/週/月切替
- 期間移動
- 教材フィルタ

推移/内訳領域には `この期間にはまだ学習記録がありません` のような空状態を表示する。

旧画面のように大部分が無意味な空白だけになる状態を避ける。

## 14. Navigation and chrome

ホームの「今週の進捗 > 詳細を見る」から開けること。

レポート画面から戻るとホームへ戻れること。

画面下部には既存 `PrimaryBottomNav` を表示する。

`AppViewSwitcher` は表示しない。

レポート閲覧中のPrimaryBottomNavはホーム由来の二次画面であることを踏まえ、独立した「レポート」active itemは追加しない。ホームをactive扱いとする。

## 15. Visual design

現行Home/Bookshelf/ScheduleのUI言語へ合わせる。

- 白/テーマsurfaceを基調
- 青を主要accent
- 薄いborder
- 小さすぎない角丸
- 数値を主役にしたカード
- 補助テキストは低コントラスト
- 不要な影やグラデーションを増やさない

生成プレビューのレイアウトを方向性として利用するが、実装では既存CSS tokenを優先し、画像をピクセル単位で模写しない。

スマートフォンの最初のviewportで、4サマリーと期間粒度切替が確認できる密度を目標とする。

## 16. Responsive requirements

主要対象はスマートフォン。

- 360px級でも横スクロールを起こさない
- 4サマリーは2列×2行
- 長い教材名はtruncate/wrapでcontainする
- 月表示グラフはラベルを間引く等で可読性を維持する
- bottom navigationと本文が重ならない

タブレット/デスクトップでは横幅を利用してサマリーや内訳の密度を改善してよいが、別機能を追加しない。

## 17. Accessibility requirements

- 戻る、前期間、次期間等のアイコンボタンにaria-labelを設定する
- 日/週/月切替はキーボード操作可能にする
- 教材フィルタはlabelを持つ
- グラフにアクセシブルな要約を持たせる
- focus-visibleを既存UIと同等に維持する
- 選択状態やデータ系列を色だけで表現しない

## 18. Data invariants

同じActual集合から計算される以下の値は一致すること。

`対象期間合計 = グラフbucket合計 = 内訳合計`

教材フィルタ適用時も同じ不変条件を維持する。

今日・今週・今月・累計サマリーも同じActual時間算出規則を使用する。

Actual時間は既存domain contractに従い、終了時刻と開始時刻から負値や不正値を生成しない。

表示用丸めによって内部合計の整合性を壊さない。

## 19. Implementation boundaries

- 集計ロジックをJSX内へ散らさない
- ReportView専用のdeterministic集計helper/modelへ分離する
- 永続化方式をReportViewへ持ち込まない
- 既存Actual/Plan/Material型を不必要に変更しない
- 新しいchart dependencyは追加しない。MVPはCSS/HTMLで実装する
- AI/LLM依存を追加しない

## 20. Acceptance criteria

1. ホームの「今週の進捗 > 詳細を見る」から新レポートへ遷移できる。
2. 今日・今週・今月・累計の学習時間が画面上部に表示される。
3. 日・週・月を切り替えられる。
4. 表示期間を前後へ移動できる。
5. 教材フィルタが機能する。
6. 対象期間の学習時間推移が表示される。
7. 教材・科目別の内訳が表示される。
8. 対象期間合計、グラフ合計、内訳合計が一致する。
9. 空期間でも画面構造が崩れない。
10. `AppViewSwitcher` がレポート画面に表示されない。
11. `PrimaryBottomNav` が維持され、ホームをactiveとして扱う。
12. 360px級モバイルで横にはみ出さない。
13. ライト/ダーク双方で既存theme contractを壊さない。
14. 既存の予定、実績保存、教材、ホーム、時間割の挙動を壊さない。
15. TypeScript、unit/component tests、production build、関連Browser Regressionが通る。
