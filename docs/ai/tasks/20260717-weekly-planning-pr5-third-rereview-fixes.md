# PR5 三回目再レビュー指摘を修正する

Status: open
Created: 2026-07-17

## 目的

PR #5 の head `0d3cb69f8ad6ba02af7dadc89fc17c3f3117975b` に対する再レビューで確認された、期間名だけの未来期間が保持されない問題、来週の範囲外日付を確定してしまう問題、保存データ検査と回帰テストの不足を修正する。

## 確認済みの問題

### 1. 「夏休みに計画を立てたい」を途中状態として保持できない

期間名として「夏休み」が明示されていても、「一週間」または「来週」が含まれないと未確定期間を生成しない。そのため、次の発話で日付と期間が補われても、前の発話の期間名を保持・結合した会話になっていない。

### 2. 来週の範囲外にある絶対日付を確定してしまう

来週の開始日を確認中でも、後続発話に絶対日付が含まれると、その日付が来週の範囲内か確認せず確定する。AI候補経路は範囲外を確認待ちにするため、決定的な解析経路とAI経路で挙動が一致していない。

### 3. 仮予定の判断タグを任意文字列として復元できる

仮予定生成側が使用する判断タグは有限集合だが、保存データの検査では任意の文字列を許可している。不明なタグを含むnested metadataも正常なsessionとして復元される。

### 4. 実利用経路のテストがまだ分割されている

Promise待機中の画面開閉テストは、画面上の入力欄と送信ボタンを操作せず内部handleを直接呼んでいる。また、再表示後にユーザーとassistantの会話が表示されることを確認していない。保存時の一時情報除去テストも、同じfixture内で会話messageの保持を確認していない。

## 実装方針

1. 期間名「夏休み」を単独で含む計画依頼でも、日数未確定の未来期間として保持する。
2. 後続発話の日付と期間を、保持済みの未来期間と結合して確定する実reducer経路をテストする。
3. 来週の途中状態では、絶対日付も保持済みの日付枠内にある場合だけ確定する。枠外は途中状態を維持する。
4. 仮予定と昇格後予定の判断タグを、生成側と同じ有限集合で検査する。
5. lifecycle testは画面上の「週間計画」選択、入力、送信を実際に操作し、再表示後にユーザー発話、assistant応答、仮予定、昇格操作を確認する。
6. v2と旧形式の一時情報除去fixtureへ会話messageも入れ、一時情報だけ除去されることを同時に確認する。
