# Appから週間計画の進行・承認・画面接続を分離する

Status: completed / automated verified
Priority: P1
Issue: #49
Pull request: #50

## 1. 背景

`src/App.tsx`はアプリ全体の画面構成に加えて、週間計画について次の責務を直接担当していた。

- 週間計画の状態初期化
- 会話処理の開始、中止、履歴消去、セッション初期化
- 非同期処理の実行依存の組み立て
- 仮予定の承認前検証
- 仮予定から通常予定への保存
- 承認履歴の読み込み、更新、localStorage保存
- クイック追加画面への週間計画用props接続
- 週表示・日表示への仮予定接続

この状態では、週間計画の内部変更が`App.tsx`へ波及し、アプリ全体の画面変更と衝突しやすかった。また、承認処理と会話処理のテストが画面ルートへ引き上げられ、責務境界が不明瞭だった。

## 2. 目的

週間計画の進行管理、仮予定承認、画面接続を週間計画専用のアプリケーション層へ移し、`App.tsx`を次の責務へ限定する。

- アプリ全体の認証・画面切替
- 他機能から週間計画へ渡す外部データの選択
- 週間計画用の専用接続componentの配置

## 3. 実装内容

### 3.1 週間計画アプリケーション層

専用hookへ次を集約した。

- 週間計画状態の読み込みと保存
- 1回の会話処理を管理するsessionの保持
- 会話送信、中止、履歴消去、セッション初期化
- 仮予定候補と下書きの追加・削除
- 仮予定承認処理の呼び出し
- 承認履歴の読み込みと保存

既存のreducer、turn controller、turn executorを再利用し、会話処理や状態遷移は複製していない。

### 3.2 承認アプリケーション処理

仮予定の承認について、次を`App.tsx`から専用処理へ移した。

- 古くなった仮予定の拒否
- 未確認の仮定を含む仮予定の拒否
- 同じ仮予定に対する既存承認履歴の再利用
- 保存済み予定の確認
- 仮予定から通常予定への変換と保存
- 一部失敗時の未保存分再試行
- 保存完了・失敗の会話状態への反映

### 3.3 承認履歴の保存

承認履歴のlocalStorage読み書きを専用storageへ移した。`App.tsx`は保存形式や保存キーを知らない。

### 3.4 画面接続

クイック追加画面への週間計画用の状態・操作の接続を専用componentへ移した。

`App.tsx`は次だけを担当する。

- 週間計画アプリケーション層へ利用者、日付、既存予定、時間割、保存関数を渡す
- 週表示・日表示へ仮予定一覧と削除操作を渡す
- 専用のクイック追加接続componentを配置する

### 3.5 責務境界テスト

`App.tsx`へ次の実装詳細が戻った場合に失敗する構造テストを追加した。

- 会話処理の直接実行
- 仮予定承認の直接実行
- 承認前検証の直接実行
- 承認履歴の直接保存
- クイック追加画面への週間計画用propsの個別列挙

## 4. 現在の依存方向

```text
App
  -> 週間計画アプリケーションhook
       -> reducer / turn controller / turn executor
       -> 承認アプリケーション処理
            -> approval domain
       -> 承認履歴storage
  -> 週間計画用クイック追加接続component
       -> QuickEntryModal
```

UI componentから`App`固有の状態へ逆参照せず、週間計画のdomain処理もReact component型へ依存しない。

## 7. 全体監査

### 7.1 解消した問題

- `App.tsx`は週間計画の処理手順、承認手順、保存形式を持たなくなった。
- 週間計画変更時に、アプリ全体の画面ルートへ大規模な修正を入れる必要がなくなった。
- 会話進行と仮予定承認の入口が週間計画専用層へまとまった。
- 画面接続の大量のpropsが`App.tsx`から消えた。
- 今後`App.tsx`へ責務が戻る回帰を自動検出できる。

### 7.2 P1: 複数端末での承認重複

現在の承認履歴はブラウザ内に保存され、保存済み判定も読み込み済み予定を基準にしている。同じ端末での再試行には対応できるが、複数タブ・複数端末から同時承認した場合の一意性は保証できない。

後続Issue: #51 `仮予定承認を複数端末でも重複させない`

サーバー側で承認番号と保存結果を一意に管理するまで、複数端末安全性は未完了とする。

### 7.3 P2: 週間計画画面と汎用AI入力画面の混在

`QuickEntryModal`と`NaturalLanguageAssistant`は、手動予定、Todo、実績記録、単発AI提案、週間計画の会話、仮予定の時間割表示、承認操作を同時に担当している。

`App`からの接続は整理されたが、画面部品内部の責務集中は残る。

後続Issue: #52 `週間計画画面を汎用AI入力画面から分離する`

### 7.4 会話処理の内部境界

reducer、turn controller、turn executor、intake pipelineを確認した結果、現時点で重大な処理重複は確認されなかった。

- reducer: 許可された状態遷移
- turn controller: 非同期処理の所有権と古い結果の排除
- turn executor: 1回の発話処理に必要な依存の組み立て
- intake pipeline: 発話解釈、状態更新、次の質問、仮予定生成

この分担は維持する。アプリケーションhookへ会話解釈や状態遷移を移さない。

### 7.5 会話記録と個別設定

会話記録は通常の週間計画状態・承認履歴と別の保存境界にあり、今回の責務分離で混在していない。

残る運用作業はIssue #45、長期個別設定と週始まりはIssue #47 / PR #48で管理する。PR #48は本PRのアプリケーション層を利用し、週間計画の実装詳細を`App.tsx`へ戻さない形へ取り込む必要がある。

### 7.6 実ブラウザ確認

自動テストでは確認できない次の操作はIssue #43に残っている。

- 処理中に画面を閉じて再表示した場合の復元
- 対象週変更後に古い結果が表示されないこと
- 中止・初期化後に古い結果が表示されないこと
- 日本語入力変換中の誤送信防止
- 処理終了後の入力欄フォーカス
