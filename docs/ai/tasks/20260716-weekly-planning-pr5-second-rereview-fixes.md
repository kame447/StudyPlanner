# PR5 二回目再レビュー指摘を修正する

Status: open
Created: 2026-07-16

## 目的

PR #5 の head `8cdf0ea07918fd5f2795282cbe20a93229d34937` に対する二回目の再レビューで確認された、保存済み仮予定の消失、未来期間の会話進行不能、重要経路のテスト不足を修正する。

## 確認済みの問題

### 1. 正常な仮予定を再読込すると相談全体が消える

通常タスクから生成される仮予定は、仮予定段階の判断情報を持つ。一方、保存データの検査は、承認後の予定候補だけが持つ追加情報まで必須としている。このため、アプリ自身が生成した正常な仮予定を不正と判定し、会話、入力済み条件、仮予定を含むsession全体を初期化する。

### 2. 「夏休み」へ後続の日付を追加しても期間が確定しない

「夏休みの一週間で計画を立てたい」で示された7日間が途中状態へ保存されない。また、途中状態が存在すると、次の発話に含まれる日付や期間を読む前に処理を終了する。AIが完全な日付範囲を返した場合も、日付枠を持たない未来期間を機械的に確認待ちへ送り、適用しない。

### 3. 重要な実利用経路がテストされていない

AI処理中にモーダルを閉じ、処理完了後に開き直す実際のPromiseとcomponent lifecycleが固定されていない。保存データから承認処理中の一時情報を除去するテストも、実際の承認処理中データをfixtureへ入れていない。

## 実装方針

1. 仮予定段階の判断情報と、承認後の予定候補の判断情報を別々の規則で検査する。
2. アプリが実際に生成する形の仮予定、会話、入力済み条件を保存し、再読込後にすべて復元できることを固定する。
3. 今回の発話に含まれる明示日付と期間を先に読み、前の発話から保持した情報と組み合わせて計画期間を確定する。
4. 「来週」のように日付枠が決まっている途中状態だけ日付枠内か確認し、「夏休み」のように日付枠が未確定な状態は、完全な明示期間が入力された時点で確定する。
5. 実Promiseを待機させたままモーダル子componentをunmountし、完了後にremountして仮予定が表示されるテストを追加する。
6. v2と旧形式の双方へ実際の承認処理中データを入れ、読込時に除去されることを確認する。
