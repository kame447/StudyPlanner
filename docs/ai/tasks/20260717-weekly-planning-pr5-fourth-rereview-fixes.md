# PR5 四回目再レビュー指摘を修正する

Status: open
Created: 2026-07-17

## 目的

PR #5 の head `470c13a5920b7c8a797b9c276e33f4cdf47963a5` に対する再レビューで確認された、空白入り月日を曜日として再解釈する問題、`夏休み`を含むタスク発話まで期間指定として扱う問題、昇格後予定の保存検査テスト不足を修正する。

## 確認済みの問題

### 1. 明示月日を拒否した後に曜日として読み直す

来週の範囲外にある`8月1 日から一週間`を明示日付として認識した後、範囲外なので不採用にする。しかし同じ文章を曜日解析へfallbackし、空白直後の`日`を日曜日として再解釈して来週の日曜日から確定してしまう。全角数字も正規化後に同じ経路へ入る。

### 2. `夏休み`を含むだけで期間pendingを生成する

`夏休みの宿題は数学ワーク10ページです`のようなタスク発話でも、`夏休み`という語だけで未来期間pendingを生成する。その結果、確定済みrangeと新しいpendingが同時に存在し、計画開始日の確認が再発する。`夏休みではなく来週`のような否定表現も誤って夏休みを採用する。

### 3. 昇格後予定の未知tag拒否を自動テストしていない

production validatorは仮予定と昇格後予定の両方で未知の配置判断tagを拒否するが、negative testは仮予定だけを固定している。

## 実装方針

1. 明示月日を認識した発話は、日付枠外で不採用になっても曜日解析へfallbackしない。
2. 曜日解析前に月日tokenを除外し、半角・全角数字および数字と`日`の間の空白に依存しない区別へ変更する。
3. `夏休み`の未来期間pendingは、明示的な計画期間の依頼がある場合、または直前状態が期間回答を要求している場合だけ生成する。
4. `夏休みではなく来週`などの否定・対比では夏休みを採用しない。
5. 確定済みrangeを持つ状態で夏休みの宿題を追加しても、rangeを維持し新しいpendingを作らない実pipeline testを追加する。
6. 昇格後draftの未知tagをsession全体として拒否するstorage testを追加する。
