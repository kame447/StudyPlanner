# PR5 四回目再レビュー指摘を修正する

Status: closed
Created: 2026-07-17
Closed: 2026-07-17

## 目的

PR #5 の head `470c13a5920b7c8a797b9c276e33f4cdf47963a5` に対する再レビューで確認された、空白入り月日を曜日として再解釈する問題、`夏休み`を含むタスク発話まで期間指定として扱う問題、昇格後予定の保存検査テスト不足を修正する。

## 確認済みの問題

### 1. 明示月日を拒否した後に曜日として読み直す

来週の範囲外にある`8月1 日から一週間`を明示日付として認識した後、範囲外なので不採用にしていた。しかし同じ文章を曜日解析へfallbackし、空白直後の`日`を日曜日として再解釈して来週の日曜日から確定していた。全角数字も正規化後に同じ経路へ入っていた。

### 2. `夏休み`を含むだけで期間pendingを生成する

`夏休みの宿題は数学ワーク10ページです`のようなタスク発話でも、`夏休み`という語だけで未来期間pendingを生成していた。その結果、確定済みrangeと新しいpendingが同時に存在し、計画開始日の確認が再発していた。`夏休みではなく来週`のような否定表現も誤って夏休みを採用していた。

### 3. 昇格後予定の未知tag拒否を自動テストしていない

production validatorは仮予定と昇格後予定の両方で未知の配置判断tagを拒否していたが、negative testは仮予定だけを固定していた。

## 実装結果

### 明示月日と曜日の解析経路を分離

明示月日を認識した発話は、保持中の日付枠外で不採用になった場合も曜日解析へfallbackしないようにした。曜日解析前には月日tokenを除外するため、半角・全角数字、数字と`日`の間の空白に依存せず、月日表現と曜日表現を区別する。

次を回帰テストへ追加した。

- `8月1日から一週間`
- `8月1 日から一週間`
- `９月１０ 日から一週間`
- `日曜から`
- `日曜日から`
- `月曜から`

### `夏休み`を期間として採用する条件を限定

`夏休み`は、計画・予定・スケジュールを作る明示的な依頼がある場合に未来期間として採用する。期間回答を求めている直前状態では、短答の`夏休み`も受理する。

一方、次の発話では未来期間pendingを生成しない。

- `夏休みの宿題は数学ワーク10ページです`

また、`夏休みではなく来週の計画を立てたい`では否定された夏休みを採用せず、来週を保持する。確定済みrangeを持つ状態で夏休みの宿題を追加しても、rangeを維持しpendingPlanningRangeを生成しない実pipeline testを追加した。

### 昇格後draftの未知tag拒否を固定

昇格後draftのbehavior metadataへ未知の配置判断tagを入れた保存データが、session全体として拒否されるnegative testを追加した。
