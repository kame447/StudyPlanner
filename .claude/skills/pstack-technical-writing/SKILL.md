# Technical writing (adapted from pstack)

Source: https://github.com/backnotprop/pstack/blob/main/skills/technical-writing/SKILL.md

Choose the document's purpose before drafting: tutorial (learning by doing), how-to (complete a task), reference (look up facts), or explanation (understand a concept). Keep one primary purpose per document.

Use names that match the codebase. Prefer precise everyday language, short actionable instructions, and concrete expected results. Remove filler, vague claims, decorative headings, and unsupported certainty. Preserve necessary technical detail, links to evidence, and constraints. Prefer examples that can be checked.

Do not change repository documentation conventions or AGENTS.md rules. This skill does not control agents, tool permissions, model selection, or PR lifecycle.
